## 2. Content & Clinical Review — the standout new page

Every launch gate this project has accumulated lives only in prose and JSON right now. This page is where they get closed.

| **Panel**               | **What it does**                                                                                                                                                                                                             | **Source**                                                           |
|-------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------|
| Safety templates        | View/edit M8 distress + G4 emergency template text; clinicallyReviewed toggle, reviewer name + date stamp, required before the app may serve them                                                                            | Content library, contentType: distress-template / emergency-template |
| Schedule verification   | Vaccine schedule (vaccines-en.json) and growth LMS tables (growth-lms-en.json): view current version, upload a new one, set sourceVerifiedBy (reviewer + date) — app refuses to serve an unverified schedule                 | S3 nianza-content/vaccines/, /growth-lms/                            |
| Milestone library       | View milestones-en.json version, publish updates (CDC LTSAE revisions do happen periodically)                                                                                                                                | S3 nianza-content/milestones/                                        |
| Content queue           | Daily tips, postcard/capsule templates, generational-shift content (v2.15) — these ship WITHOUT per-item review by design (v2.2 policy), but this panel is where Ej can still browse, spot-check, and pull an item if needed | Content library, all contentType rows                                |
| Golden-harness sign-off | Renders the 25-scenario transcript set (NZA-CHAT-v1.0 §5) after any prompt/model/bundle change; Ej reviews and digitally signs before the change can promote past staging                                                    | New nianza-harness-runs table                                        |

> **Warning:** Nothing in this page is a launch nicety — `sourceVerifiedBy` and `clinicallyReviewed` are hard launch gates already written into three separate specs (NZA-VACCINES-v1.0, NZA-VITALS-GROWTH-v1.0, NZA-CHAT-v1.0). Recommend building this page in Phase 1, not deferred with the rest of ops tooling.

## 3. Access Tiers & the PII/PHI View-Audit Log

Nianza admin staff can see a child's milestones, vaccine records, vitals, and chat transcripts — a materially more sensitive data class than Claricito's mood entries. The access model has to say so.

| **Role**                     | **Can see**                                                                                                                          | **Cannot see**                                                           |
|------------------------------|--------------------------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------|
| Support                      | Account status, subscription/billing state, support ticket history, aggregate (non-identifying) usage                                | Any individual child's milestones, vaccines, vitals, or chat transcripts |
| Clinical Reviewer            | Content & Clinical Review page in full; may open a specific chat transcript ONLY when investigating a flagged safety-template firing | Subscription/billing detail, other admin accounts' audit trail           |
| Full Admin (Ej + designated) | Everything, including individual child health records when a support case genuinely requires it                                      | —                                                                        |

- Every time ANY role opens an individual child or parent's health-adjacent record (milestones, vaccines, vitals, encounters, chat transcript) — not just admin actions like Claricito's Team-page audit log — write a row to a new nianza-admin-access-log: admin userId, target userId/childId, fields viewed, timestamp, and the support-ticket ID or reason code that justified the lookup. This log is append-only and itself visible only to Full Admin.

- Cognito pool for this portal is fully separate from the Nianza consumer-app pool — an admin credential must never be able to authenticate into the parent-facing app or vice versa.

## 4. Suggested Phasing (mirrors Claricito's 3A/3B/4/5/6 pattern)

| **Phase** | **Scope**                                                                                                             | **Why this order**                                                                                                                               |
|-----------|-----------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------|
| 1         | Auth scaffold (Cognito pool, invite-token onboarding, Settings) + Subscriptions/Churn/Ops + CONTENT & CLINICAL REVIEW | Revenue visibility and launch-gate closure are both day-one needs — the app cannot ship without the review page regardless of what else is built |
| 2         | Customer Service (account lookup, support actions) + access-tier enforcement + PII/PHI audit log                      | Needed as soon as real users exist and support requests start arriving                                                                           |
| 3         | Team page                                                                                                             | Straightforward, low-risk, needed once the admin team grows past founder-only                                                                    |
| 4         | Engagement + Patterns (Tier-2 aggregation pipeline, cohort-gated)                                                     | Valuable but not launch-blocking; also the pipeline needs real usage volume to be meaningful                                                     |
| 5         | Reliability/System Health/Security Compliance/Data Exports                                                            | Operational maturity layer — build once there's an operation to monitor                                                                          |

## 5. Acceptance Gates (Ej)

- Log in with an admin credential → confirm it cannot authenticate against the Nianza consumer app's Cognito pool, and vice versa.

- As Support role, attempt to open a child's milestone record → blocked; as Full Admin, open the same record → succeeds AND writes a row to nianza-admin-access-log with a reason code.

- Attempt to mark the app as ready to serve a new vaccine schedule without sourceVerifiedBy set → blocked at the publish action, not just hidden in the UI.

- Upload a golden-harness run → Ej can review and digitally sign; an unsigned run cannot be promoted.

- Confirm PatternsPage shows nothing for any cohort under the configured minimum size.

> **Definition of done:** Every launch gate this project has written down on paper finally has a button attached to it — and nobody can quietly bypass the button.
